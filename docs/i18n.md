# Languages

Atelier speaks the languages the Mac App Store lists, with its English variants counted once: 36 locales (`Locale::ALL` in
`crates/i18n`). Arabic and Hebrew are right to left. The model for this, and for the tool below, follows FluentAI's
ADR 0006: one file per string, every language in the file, and a missing language fails the build.

## A key

One file per string, next to the code that shows it, for example `crates/agents/src/strings/planning_next_moves.rs`:

```rust
pub const PLANNING_NEXT_MOVES: Message = Message { ar: "…", ca: "…", /* every locale */ zh_tw: "…" };
```

`Message` has a field for each locale. A file that leaves one out does not compile. `t(&KEY)` gives the string for the current
locale; `t_with(&KEY, &[("name", value)])` fills each `{name}`. The language starts as English; `Locale::resolve` picks one from
a list of system tags (`fr_CH.UTF-8`, `zh-Hant-HK`, `nb`) and `set_current` sets it.

## Writing a key

Nobody writes the 36 values by hand. The tool asks the model, which is `openai/gpt-6-luna` on OpenRouter. FluentAI's dev checkout on the Mac keeps an OpenRouter key
in `~/Documents/fluentai/.env.local`; the tool takes it from `OPENROUTER_API_KEY`:

```sh
OPENROUTER_API_KEY=… cargo run -p atelier-i18n --bin atelier-translate -- \
  crates/agents/src/strings planning_next_moves "Planning next moves…" \
  "Status line after a message is sent to Cursor, until it answers. About 24 characters of room."
```

The note is what a translator would ask: where the string shows and how much room it has. `--dry-run` prints the request and
sends nothing.

1. **Look up.** The glossary (`crates/i18n/src/glossary.rs`) is searched for the words in the English. A name is kept as it is in
   every language; a term with an approved word for a language is given to the model with that word.
2. **Write.** The model gets the English, the note, the glossary lines and the locale list, and answers with one JSON object of tag
   to string. It chooses the best wording for each language; it is not asked for word-for-word.
3. **Check.** Every locale is there, none is empty, every `{name}` survived, and every kept name is written exactly. A failed check
   goes back to the model once, with what failed. A second failure writes nothing.

## Many keys

`--batch <manifest>` writes a whole page of keys at once, ten requests in flight by default; a key whose file exists is skipped, and
`--force` writes it again. The manifest is `key<TAB>English<TAB>note` per line and is kept beside the files
(`crates/app/src/settings_pane/strings/manifest.tsv` is the Settings page's). A key is added to the manifest, the tool is run, and
the key's line goes into the folder's `strings.rs`. A request takes about two to five minutes; the wait is the model's, not the
tool's.

## The language setting

Settings > Appearance > Language lists "System" and the 36 languages by their own names. A pick is kept as `language` in the
settings file (its tag) and applies to every word read from then on. At start the app reads that, else the system's language.

## Not done yet

- Plurals. Values are plain strings with `{name}`; CLDR plural forms come next, and until then a key avoids counting.
- `ATELIER_LANG=ja` tries a language without keeping it.
- Text that is read once (a look's labels) stays in the language it was read in, so a change of language needs a restart.
- Right-to-left layout, and numbers and dates by locale.
- Words that live in other crates: the task rules' names (`atelier-tracker`), the sidebar's badge words and the key table
  (`atelier-ui`), and the dictation keys (`atelier-voice`). The Settings page is otherwise done.
- Every other string. About 1,800 are candidates across Atelier and atelier-ui, which is a separate repository.
